# 资产探测工具需求文档

## 简介

本文档定义了一款高性能网络资产探测工具的需求规格。该工具参考 nmap 和 masscan 的实现逻辑，用于对大规模网络（两个A段，约131,072个IP）进行主机发现、端口扫描、服务识别，并能识别网络中的代答（代理响应）资产。

## 术语表

- **A段网络**: 指一个/8网段，包含约16,777,216个IP地址；两个A段即两个/8网段
- **主机发现**: 确定目标网络中哪些IP地址有活跃主机
- **端口扫描**: 探测目标主机上开放的TCP/UDP端口
- **服务识别**: 通过指纹匹配识别开放端口上运行的服务类型和版本
- **代答资产**: 指网络中存在代理设备（如防火墙、负载均衡器、代理服务器）替后端真实服务器响应请求的情况
- **SYN扫描**: 发送SYN包，根据响应判断端口状态（半开扫描）
- **指纹匹配**: 通过比对服务返回的特征数据与已知指纹库，识别服务类型和版本
- **TTL分析**: 通过IP包的TTL值分析网络拓扑和代答情况
- **并发度**: 同时进行扫描的目标数量

## 需求

### 需求 1: 主机发现

**用户故事:** 作为安全测试人员，我希望能够快速发现目标网络中的活跃主机，以便进行后续的端口和服务扫描。

#### 验收标准

1. **WHEN** 用户指定目标网络范围，**系统 SHALL** 支持CIDR格式输入（如10.0.0.0/8, 192.168.0.0/16）
2. **WHEN** 用户指定单个或多个IP地址，**系统 SHALL** 支持逗号分隔的IP列表输入
3. **WHEN** 用户指定IP范围，**系统 SHALL** 支持范围格式输入（如10.0.0.1-10.0.0.255）
4. **WHILE** 执行主机发现，**系统 SHALL** 使用ICMP Echo Request、ARP请求（本地网络）、TCP SYN探测多种方式
5. **WHEN** 主机发现完成，**系统 SHALL** 输出所有响应主机的IP地址列表
6. **IF** 主机在指定超时时间内未响应，**系统 SHALL** 标记该主机为不可达或过滤状态

### 需求 2: 高性能端口扫描

**用户故事:** 作为安全测试人员，我希望能够在合理时间内完成大规模网络的端口扫描，以便快速了解网络暴露面。

#### 验收标准

1. **WHEN** 用户启动端口扫描，**系统 SHALL** 支持指定端口范围（如1-65535）或常用端口列表
2. **WHILE** 执行端口扫描，**系统 SHALL** 使用异步SYN扫描技术提高扫描速度
3. **WHILE** 扫描大规模网络，**系统 SHALL** 支持配置并发度和发包速率
4. **WHEN** 端口扫描完成，**系统 SHALL** 输出每个开放端口的IP地址和端口号
5. **WHILE** 扫描过程，**系统 SHALL** 实时显示扫描进度和预计剩余时间
6. **IF** 扫描过程被中断，**系统 SHALL** 支持从断点继续扫描
7. **WHEN** 用户指定TCP和UDP协议，**系统 SHALL** 支持两种协议的端口扫描

### 需求 3: 服务指纹识别

**用户故事:** 作为安全测试人员，我希望能够识别开放端口上运行的服务类型和版本，以便进行漏洞评估。

#### 验收标准

1. **WHEN** 发现开放端口，**系统 SHALL** 主动发送探测报文获取服务Banner
2. **WHILE** 分析服务响应，**系统 SHALL** 与内置指纹库进行匹配识别服务类型
3. **WHEN** 服务识别成功，**系统 SHALL** 输出服务名称、版本号和操作系统信息
4. **IF** 指纹库无法匹配，**系统 SHALL** 输出原始Banner信息供人工分析
5. **WHILE** 服务识别过程，**系统 SHALL** 支持自定义指纹规则扩展

### 需求 4: 代答资产识别

**用户故事:** 作为安全测试人员，我希望能够识别网络中的代理设备代答情况，以便准确评估真实资产。

#### 验收标准

1. **WHILE** 执行主机发现，**系统 SHALL** 统计每个C段的存活主机数量
2. **WHEN** 某C段的存活主机数量达到254或255台，**系统 SHALL** 标记该C段为疑似代答网段
3. **WHILE** 执行端口扫描，**系统 SHALL** 记录每个响应包的TTL值
4. **WHEN** 同一IP不同端口返回的TTL值存在显著差异，**系统 SHALL** 标记可能存在代答
5. **WHEN** 多个IP返回相同的服务指纹特征，**系统 SHALL** 标记可能为同一后端服务器
6. **WHILE** 分析响应特征，**系统 SHALL** 检测HTTP代理、反向代理、负载均衡等代答模式
7. **WHEN** 检测到代答情况，**系统 SHALL** 尝试推断真实后端IP和端口
8. **WHEN** 用户查看结果，**系统 SHALL** 提供代答资产与真实资产的区分展示，包含推断的后端信息

### 需求 5: 结果输出与报告

**用户故事:** 作为安全测试人员，我希望能够以多种格式导出扫描结果，以便与其他工具集成或生成报告。

#### 验收标准

1. **WHEN** 扫描完成，**系统 SHALL** 支持JSON格式输出结果
2. **WHEN** 扫描完成，**系统 SHALL** 支持CSV格式输出结果
3. **WHEN** 扫描完成，**系统 SHALL** 支持标准XML格式输出（兼容nmap格式）
4. **WHILE** 输出结果，**系统 SHALL** 包含主机IP、端口状态、服务信息、代答标记
5. **WHEN** 用户指定输出文件路径，**系统 SHALL** 将结果写入指定文件
6. **IF** 输出文件已存在，**系统 SHALL** 提供追加或覆盖选项

### 需求 6: 性能与可靠性

**用户故事:** 作为安全测试人员，我希望工具在扫描大规模网络时保持稳定可靠，以便完成完整的资产探测任务。

#### 验收标准

1. **WHILE** 扫描两个A段网络（约131,072个IP），**系统 SHALL** 在24小时以上完成全端口+服务探测
2. **WHEN** 用户指定网络范围参数，**系统 SHALL** 支持任意范围的CIDR输入，最大支持两个A段
3. **WHILE** 高并发扫描，**系统 SHALL** 内存使用不超过系统可用内存的50%
4. **IF** 网络异常或目标不可达，**系统 SHALL** 正确处理错误并继续扫描其他目标
5. **WHILE** 扫描过程，**系统 SHALL** 支持暂停和恢复功能
6. **WHEN** 扫描完成或中断，**系统 SHALL** 保存扫描状态到持久化文件

### 需求 7: 安全性与合规

**用户故事:** 作为安全测试人员，我希望工具在扫描时遵守网络安全规范，以避免对目标网络造成过大影响。

#### 验收标准

1. **WHILE** 执行扫描，**系统 SHALL** 支持配置发包速率限制，避免对目标网络造成拒绝服务
2. **WHEN** 用户指定扫描源IP，**系统 SHALL** 支持配置源IP和源端口
3. **WHILE** 扫描过程，**系统 SHALL** 记录详细的扫描日志
4. **IF** 检测到目标可能为蜜罐，**系统 SHALL** 在结果中标记警告

## 质量属性

- **性能**: 支持100,000+ PPS（每秒数据包）的扫描速率
- **准确性**: 主机发现准确率 > 95%，服务识别准确率 > 85%
- **可扩展性**: 支持插件机制扩展指纹库和探测模块
- **跨平台**: 支持Linux、macOS、Windows操作系统

## 约束条件

- 需要管理员/root权限执行原始套接字操作
- 目标网络规模：两个A段（/8网段）
- 开发语言：Go
